# `patches` 폴더 분석

이 `patches` 폴더는 프로젝트가 의존하는 외부 npm 패키지들에 대한 패치(patch) 파일들을 저장하는 데 사용되는 것으로 보입니다.

일반적으로 `pnpm patch` (또는 `yarn patch-package`와 유사한 도구)와 같은 명령을 사용하여 특정 의존성 패키지의 코드를 임시로 수정한 후, 그 변경 사항을 `.patch` 파일 형태로 저장하여 프로젝트에 포함시킵니다. 이렇게 하면 해당 패키지의 공식 릴리스에 수정 사항이 반영되기 전까지 프로젝트에서 필요한 변경을 적용한 채로 사용할 수 있습니다.

## 주요 하위 파일 (추정)

*   **`[package-name]@[version].patch`**: 특정 패키지(예: `pkce-challenge@4.1.0.patch`)의 특정 버전에 적용되는 패치 파일입니다.
    *   이 파일은 `diff` 형식으로 되어 있으며, 원본 패키지 코드와 수정된 코드 간의 차이점을 기술합니다.
    *   `pnpm install` 시점에 `pnpm`이 이 패치 파일들을 자동으로 감지하고 해당 패키지에 적용하여, 마치 수정된 코드가 원래 패키지의 일부였던 것처럼 만들어줍니다.

## 사용 이유 및 목적

*   **긴급 버그 수정**: 의존하는 외부 라이브러리에서 버그를 발견했지만, 해당 라이브러리의 새 버전이 릴리스될 때까지 기다릴 수 없을 때 사용합니다.
*   **기능 추가 또는 변경**: 외부 라이브러리에 프로젝트에 꼭 필요한 작은 기능을 추가하거나 기존 동작을 약간 수정하고 싶을 때 사용합니다. (단, 큰 변경은 해당 라이브러리에 직접 기여(contribute)하는 것이 좋습니다.)
*   **호환성 문제 해결**: 특정 버전의 라이브러리가 프로젝트의 다른 부분과 호환성 문제가 있을 때, 이를 해결하기 위해 임시로 수정할 수 있습니다.
*   **타입 정의 수정**: TypeScript 프로젝트에서 외부 라이브러리의 타입 정의(`*.d.ts`)가 부정확하거나 누락된 경우, 이를 수정하기 위해 사용될 수 있습니다.

## 관리 및 특징

*   **`pnpm`과의 통합**: `pnpm-lock.yaml` 파일에 패치 정보가 기록되어, 다른 개발자나 CI 환경에서도 동일한 패치가 일관되게 적용되도록 보장합니다. `pnpm patch-commit <patch_folder>` 명령으로 생성된 패치를 기록합니다.
*   **임시적인 해결책**: 패치는 근본적인 해결책이라기보다는 임시적인 조치로 간주되어야 합니다. 패치된 내용이 원본 라이브러리에 반영되도록 Pull Request를 보내거나, 라이브러리 업데이트 시 패치가 더 이상 필요 없는지 주기적으로 확인하는 것이 좋습니다.
*   **버전 관리**: 패치 파일은 특정 버전의 패키지에만 적용되므로, 의존성 업데이트 시 해당 패치가 여전히 유효한지, 아니면 새로운 버전에 맞게 수정해야 하는지 확인해야 합니다.

## 현재 패치 파일

*   **`pkce-challenge@4.1.0.patch`**: `pkce-challenge`라는 라이브러리의 `4.1.0` 버전에 적용되는 패치가 존재합니다. 이 패치의 내용을 분석하면 어떤 부분을 왜 수정했는지 알 수 있습니다. (OAuth 2.0의 PKCE (Proof Key for Code Exchange) 흐름과 관련된 라이브러리일 가능성이 높습니다.)

## 향후 분석 방향

*   `patches/` 폴더 내의 각 `.patch` 파일의 내용을 직접 확인하여, 어떤 라이브러리의 어떤 부분을 왜 수정했는지 구체적으로 파악합니다. 이는 프로젝트가 겪었던 특정 문제점이나 필요했던 커스터마이징을 이해하는 데 도움이 됩니다.
*   `pnpm-lock.yaml` 파일에서 해당 패치들이 어떻게 참조되고 있는지 확인합니다.
*   가능하다면, 해당 패치가 원본 라이브러리에 기여되었는지 또는 최신 버전에서는 해결되었는지 추적해 보는 것도 좋습니다.

이 폴더는 프로젝트가 외부 라이브러리와 상호작용하면서 발생할 수 있는 실제적인 문제들을 어떻게 해결해 나가는지 보여주는 좋은 예시가 됩니다.
