# `scripts` 폴더 분석

이 `scripts` 폴더는 프로젝트의 개발, 빌드, 테스트, 배포 등 다양한 프로세스를 자동화하고 지원하기 위한 스크립트 파일들을 포함하고 있습니다. 이러한 스크립트들은 주로 셸 스크립트(예: Bash), JavaScript/TypeScript (Node.js 환경에서 실행) 등으로 작성될 수 있습니다.

## 주요 하위 폴더 및 파일 (추정)

*   **`merge-yml/`**:
    *   `merge-yml.ts`: 여러 YAML 파일을 병합하는 TypeScript 스크립트로 보입니다. 이는 설정 파일 관리, CI/CD 파이프라인 설정 등 다양한 용도로 사용될 수 있습니다. 예를 들어, 기본 설정과 환경별 설정을 분리한 뒤 병합하여 최종 설정을 생성하는 데 사용될 수 있습니다.

*   **`release-beta-pkgs.sh`**: 베타 버전의 패키지를 릴리스(배포)하기 위한 셸 스크립트입니다. 모노레포 내의 특정 패키지 또는 전체 패키지의 베타 버전을 빌드하고, 버전 번호를 업데이트하며, npm 레지스트리나 다른 배포 채널에 게시하는 과정을 자동화할 수 있습니다.

*   **`release-pkgs.sh`**: 정식 버전의 패키지를 릴리스하기 위한 셸 스크립트입니다. `release-beta-pkgs.sh`와 유사하지만, 정식 릴리스를 위한 추가적인 단계(예: Git 태그 생성, 변경 로그 업데이트)를 포함할 수 있습니다.

*   **`vitest-setup.ts`**: `Vitest` 테스트 프레임워크를 위한 설정 파일 또는 초기화 스크립트로 보입니다. 테스트 실행 전에 필요한 전역 설정, 목(mock) 객체 설정, 환경 변수 설정 등을 수행할 수 있습니다. 프로젝트 전반의 테스트 환경 일관성을 유지하는 데 도움을 줍니다.

## 예상되는 내용 및 기능

*   **빌드 스크립트**: TypeScript 컴파일, 코드 번들링, 최적화 등 소스 코드를 실행 가능한 형태로 변환하는 작업을 수행합니다.
*   **테스트 실행 스크립트**: 단위 테스트, 통합 테스트, E2E 테스트 등을 실행하고 결과를 보고하는 스크립트입니다.
*   **개발 환경 스크립트**: 로컬 개발 서버 실행, 파일 변경 감지 및 자동 재빌드, 디버깅 도구 실행 등을 지원합니다.
*   **배포 스크립트**: 빌드된 애플리케이션이나 패키지를 서버, npm 레지스트리, GitHub Releases 등 다양한 환경에 배포하는 작업을 자동화합니다.
*   **코드 품질 관리 스크립트**: 린팅(Linting), 코드 포맷팅, 정적 분석 등을 실행하여 코드 품질을 일정하게 유지합니다.
*   **유틸리티 스크립트**: 파일 시스템 작업, 환경 변수 관리, Git 관련 작업 등 개발 과정에서 반복적으로 수행되는 작은 작업들을 자동화합니다.

## 특징

*   **자동화**: 반복적인 개발 작업을 자동화하여 개발 생산성을 높이고 실수를 줄입니다.
*   **일관성**: 모든 개발자가 동일한 방식으로 빌드, 테스트, 배포 등의 작업을 수행하도록 하여 일관성을 유지합니다.
*   **프로젝트 맞춤형**: 프로젝트의 특정 요구사항과 구조에 맞춰 스크립트가 작성됩니다. 예를 들어, 모노레포 환경에서는 여러 패키지를 순차적으로 또는 병렬적으로 처리하는 로직이 포함될 수 있습니다.

## 의존성 관계 (추정)

*   이 폴더의 스크립트들은 프로젝트 루트의 `package.json`에 정의된 개발 의존성(devDependencies)을 활용할 가능성이 높습니다 (예: `vitest`, `typescript`, `eslint` 등).
*   릴리스 스크립트(`release-beta-pkgs.sh`, `release-pkgs.sh`)는 `pnpm`, `turbo` (모노레포 빌드 도구), `changeset` (버전 관리 및 변경 로그 생성 도구 - `.changeset` 폴더 존재로 추정) 등의 도구를 내부적으로 호출할 수 있습니다.
*   `vitest-setup.ts`는 `vitest.config.mts` 또는 `vitest.workspace.mts` 파일과 함께 작동하여 테스트 환경을 구성합니다.

## 향후 분석 방향

*   각 스크립트 파일의 내용을 직접 분석하여 정확히 어떤 작업을 수행하는지, 어떤 도구들을 사용하는지 파악합니다.
*   루트 `package.json`의 `scripts` 섹션과 이 폴더의 스크립트들이 어떻게 연관되어 호출되는지 확인합니다.
*   CI/CD 설정 파일(`.github/workflows/`)에서 이 스크립트들이 어떻게 활용되는지 살펴봅니다. 예를 들어, 특정 워크플로우 단계에서 이 스크립트들이 실행될 수 있습니다.
*   프로젝트의 전체적인 빌드, 테스트, 배포 파이프라인을 이해하는 데 중요한 단서가 되므로, 다른 부분(예: `turbo.json`, `.changeset/config.json`)과의 연관성을 함께 분석합니다.
