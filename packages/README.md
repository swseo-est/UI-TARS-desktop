# `packages` 폴더 분석

이 `packages` 폴더는 모노레포 내의 다른 애플리케이션(`apps/`)이나 모듈(`multimodal/`)에서 공통적으로 사용될 수 있는 재사용 가능한 라이브러리 및 유틸리티 패키지들을 포함하고 있습니다. PNPM 워크스페이스 설정을 통해 이곳의 패키지들은 다른 프로젝트에서 쉽게 임포트하여 사용할 수 있게 됩니다.

## 주요 하위 폴더 (패키지) 및 역할 (추정)

*   **`agent-infra/`**: AI 에이전트 시스템을 구축하고 운영하는 데 필요한 기반 인프라 관련 모듈들을 모아놓은 것으로 보입니다.
    *   **`browser/`**: 웹 브라우저를 프로그래밍 방식으로 제어(예: Puppeteer, Playwright)하는 기능, 웹 페이지 콘텐츠 추출, DOM 조작 등의 기능을 제공하는 패키지일 것입니다. 에이전트가 웹 기반 작업을 수행하는 데 필수적입니다.
    *   **`browser-use/`**: 브라우저 사용과 관련된 유틸리티나 특정 사용 사례를 위한 모듈일 수 있습니다. `browser/` 패키지를 더 쉽게 사용하도록 돕거나 특정 작업을 추상화한 것일 수 있습니다.
    *   **`create-new-mcp/`**: "MCP" (아마도 `multimodal/mcp-agent/`와 관련된) 에이전트 또는 관련 구성 요소를 생성하기 위한 템플릿이나 스캐폴딩 도구일 수 있습니다.
    *   **`logger/`**: 시스템 전반의 로깅 기능을 제공하는 패키지입니다. 다양한 로그 레벨, 로그 포맷, 로그 저장소(파일, 콘솔, 원격 서버 등)를 지원할 수 있습니다.
    *   **`mcp-benchmark/`**: MCP 에이전트의 성능을 벤치마킹하는 도구나 스크립트를 포함할 수 있습니다.
    *   **`mcp-client/`**: MCP 에이전트 또는 MCP 시스템과 통신하는 클라이언트 라이브러리일 수 있습니다.
    *   **`mcp-http-server/`**: MCP 관련 기능을 HTTP API로 제공하는 서버 구현체일 수 있습니다.
    *   **`mcp-servers/`**: MCP와 관련된 다양한 서버 모듈(예: 브라우저 제어 서버, 파일 시스템 접근 서버)을 포함할 수 있습니다.
    *   **`mcp-shared/`**: MCP 관련 클라이언트, 서버, 에이전트 등에서 공통으로 사용되는 데이터 구조, 타입 정의, 유틸리티 함수 등을 포함할 수 있습니다.
    *   **`search/`**: 웹 검색 엔진(예: Google, Bing, DuckDuckGo) API 연동, 검색 결과 처리 등 검색 관련 기능을 제공하는 패키지입니다. 에이전트가 정보 수집을 위해 사용합니다.
        *   `bing-search/`, `duckduckgo-search/`, `browser-search/`: 특정 검색 엔진 또는 브라우저 기반 검색 기능을 제공하는 하위 모듈일 수 있습니다.
    *   **`shared/`**: `agent-infra/` 내의 여러 패키지에서 공통적으로 사용되는 유틸리티나 코드 조각들을 모아놓은 패키지일 수 있습니다.

*   **`common/`**: 프로젝트 전반에 걸쳐 사용될 수 있는 매우 일반적인 유틸리티나 설정 관련 패키지를 포함할 수 있습니다.
    *   **`configs/`**: ESLint, Prettier, TypeScript 등 공통 개발 도구 설정을 관리하는 패키지일 수 있습니다.
    *   **`electron-build/`**: Electron 애플리케이션(`apps/ui-tars/`)의 빌드 및 패키징과 관련된 공통 스크립트나 설정을 제공할 수 있습니다.

*   **`ui-tars/`**: `apps/ui-tars/` 데스크톱 애플리케이션 및 `multimodal/agent-tars-web-ui/` 웹 애플리케이션과 관련된 UI 컴포넌트, SDK, 핵심 로직 등을 모아놓은 패키지 그룹으로 보입니다.
    *   **`action-parser/`**: 사용자 입력이나 LLM의 출력을 해석하여 에이전트가 수행할 구체적인 액션으로 변환하는 파서(parser) 로직을 포함할 수 있습니다.
    *   **`cli/`**: `ui-tars` 관련 기능을 CLI 환경에서 사용할 수 있도록 하는 도구일 수 있습니다. ( `multimodal/agent-tars-cli/` 와의 관계 확인 필요)
    *   **`electron-ipc/`**: Electron 환경에서 메인 프로세스와 렌더러 프로세스 간의 IPC(Inter-Process Communication)를 처리하는 로직이나 유틸리티를 제공합니다.
    *   **`operators/`**: 에이전트가 특정 작업을 수행하기 위해 사용하는 "오퍼레이터"들을 정의하는 곳으로 보입니다. 오퍼레이터는 특정 도구나 API를 추상화한 것일 수 있습니다.
        *   `adb/`: Android Debug Bridge (ADB)를 이용해 안드로이드 장치를 제어하는 오퍼레이터일 수 있습니다.
        *   `browser-operator/`: 웹 브라우저를 제어하는 오퍼레이터입니다.
        *   `browserbase/`: `BrowserBase` (아마도 외부 서비스 또는 라이브러리)를 사용하는 오퍼레이터입니다. (`examples/operator-browserbase/` 와 연관)
        *   `nut-js/`: `nut.js` 라이브러리를 사용하여 데스크톱 GUI 자동화(마우스, 키보드 제어)를 수행하는 오퍼레이터일 수 있습니다.
    *   **`sdk/`**: `ui-tars` 애플리케이션 또는 TARS 에이전트의 기능을 외부에서 사용하거나 연동할 수 있도록 제공하는 SDK(Software Development Kit)입니다.
    *   **`shared/`**: `packages/ui-tars/` 내의 여러 하위 패키지에서 공통으로 사용되는 코드, 타입, 유틸리티 등을 포함합니다.
    *   **`utio/`**: "UI TARS I/O" 또는 유사한 의미로, UI TARS 시스템의 입력/출력 처리와 관련된 모듈일 수 있습니다.
    *   **`visualizer/`**: 에이전트의 작업 과정, 데이터 흐름, 또는 결과물을 시각화하는 컴포넌트나 도구일 수 있습니다.

## 특징

*   **공유 라이브러리**: 이 폴더의 패키지들은 프로젝트 내 여러 부분에서 재사용되어 코드 중복을 줄이고 일관성을 유지하는 데 기여합니다.
*   **인프라 및 핵심 유틸리티 제공**: 에이전트 실행에 필요한 저수준 인프라(브라우저 제어, 검색, 로깅)와 고수준 유틸리티(SDK, 오퍼레이터)를 모두 제공합니다.
*   **관심사 분리**: 각 패키지는 특정 기능(예: 로깅, 검색, 특정 오퍼레이터)에 집중하여 개발되어 유지보수성을 높입니다.
*   **모노레포의 핵심**: 모노레포 아키텍처에서 공통 코드 관리의 중심적인 역할을 수행합니다.

## 의존성 관계 (추정)

*   `apps/ui-tars/`는 `packages/ui-tars/sdk/`, `packages/ui-tars/electron-ipc/`, `packages/common/electron-build/` 등에 의존할 가능성이 높습니다.
*   `multimodal/` 내의 다양한 에이전트 패키지들은 `packages/agent-infra/`의 여러 모듈(예: `browser/`, `search/`, `logger/`)에 의존할 것입니다.
*   `packages/ui-tars/operators/`의 오퍼레이터들은 `packages/agent-infra/browser/`와 같은 저수준 모듈을 사용하거나, `nut.js`와 같은 외부 라이브러리에 직접 의존할 수 있습니다.

## 향후 분석 방향

*   각 패키지의 `package.json`을 상세히 분석하여 외부 라이브러리 의존성 및 내부 패키지 간의 정확한 의존 관계를 파악합니다.
*   `agent-infra/`의 주요 패키지들(`browser/`, `search/`, `logger/`)의 `src/` 디렉토리 내용을 분석하여 실제 구현 방식을 이해합니다.
*   `packages/ui-tars/sdk/`의 API를 분석하여 `ui-tars` 시스템이 외부 또는 내부의 다른 모듈에게 어떤 기능을 제공하는지 파악합니다.
*   `packages/ui-tars/operators/` 내부의 각 오퍼레이터가 어떤 작업을 수행하며, 어떤 기술을 기반으로 하는지 분석합니다.
*   `packages/common/` 폴더의 패키지들이 프로젝트 전반의 개발 환경 및 빌드 프로세스에 어떤 영향을 미치는지 확인합니다.
